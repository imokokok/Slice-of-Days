# 料理玩法细化

## 参考判断

本轮参考用户提供的 [Venba 操作视频](https://www.xiaohongshu.com/discovery/item/697364cf000000002203a563)，只吸收交互组织方式，不复制菜品、美术、对白或关卡内容。

最值得保留的不是“点食材”本身，而是以下节奏：

1. 镜头和注意力始终围绕一口锅，玩家能直接看到动作落点。
2. 一道菜被拆成连续的小动作；每次只需要理解眼前一步。
3. 菜谱给提示而非代替操作，玩家仍要观察火候并作决定。
4. 锅里的状态、短句和声音立即回应动作，等待不等于空白。
5. 失误改变成品记录，但不会把整段剧情截断；下一步仍能补救。
6. 料理结果回到人物关系与记忆，而不是只弹一个分数。

## 当前可玩流程

`选材 → 备料 → 下锅 → 翻拌 → 尝味 → 装盘 → 出餐`

- **选材**：从真实厨房库存选择三样材料。先挑进托盘，不等于被锁死成唯一制作顺序。
- **备料**：每样材料提供两种合理处理，例如柠檬可挤汁或留薄片、面包可留大块或撕小块；没有假选项，两种都会改变口感描述和入锅提示。
- **下锅**：玩家可重新决定三样材料的实际顺序。菜谱只描述感官提示；玩家根据“锅底安静、温热、稳定滋响、火声变急、起烟”调整火候。每样冷食材入锅后会按自身属性带走一部分锅温，下一步需要重新观察，而不是重复同一数值。
- **翻拌**：可在“轻推锅底”和“翻起拌匀”之间自由选择；手法会与当前火候互相回应。至少两下后由玩家决定立刻尝味，或最多再照看两下，不再强制固定三次。
- **尝味**：系统根据已经使用的材料给出味觉描述，玩家决定提亮、补盐或停手。
- **装盘**：在留白、丰盛、分食三种端法间做最后决定。它不额外判输赢，但成为这道菜的过程记忆。
- **出餐**：仍保留即兴新菜与稳定菜单两种原叙事结果，并沿用 90 分钟班次、工资、食材消耗和公共作品逻辑。

## 反馈与结果

过程使用三个不阻断剧情的完成层级：

- `从容出锅`：下锅、翻拌和调味都回应了锅里的变化。
- `稳当成菜`：中途有调整，但最终接住了味道。
- `带着临场痕迹`：火候或调味留下偏差，仍能作为一次完整做饭经历出餐。

记录写入 `outcome.interaction.mechanic`，包括：

- `prepared_tokens`
- `preparations`：每样食材选择的处理方式、描述和由此得到的感官提示
- `additions`：实际下锅顺序、下锅前后火候、反馈状态与本步记录值
- `stirs` / `stir_count`
- `seasoning` / `seasoning_label`
- `plating` / `plating_label`
- `craft_score` / `grade`

公共菜谱的说明会从这份真实操作记录生成，不再使用统一的“温热拌匀”占位文字。食材只在最终确认出餐后消耗；重新开始或离开料理台不会提前扣除库存。

## 美术与声音交接位

目前继续使用既有锅具、案台、菜谱和食材图。后续正式素材可以按以下状态逐项替换，不需要改玩法状态机：

- 每样食材：原始、备好、下锅、熟成四态。
- 锅：空锅、温热、稳定滋响、急火、起烟、完成六态。
- 操作：切/撕/擦干/沥水的分支动作、逐样落锅、轻推/翻起两种翻拌、尝味、三种装盘。
- 声音：轻微预热、正常滋响、急火、每种食材落锅、木勺翻拌、装盘。
- 成品：按三样材料组合及完成层级选择呈现，不把完成层级表现成刺眼的星级评分。

食材 ID、`cooking` 模块 ID、两个出餐 choice ID 和经济结算接口保持不变。
