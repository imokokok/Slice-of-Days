# 第八阶段：第七天动态结局回响

## 目标

让结局记住玩家真正做过的事，而不是只显示一组预先写好的总结。审核仍只由每位主角是否取得十二份有效认可决定；回声只改变最后留下的物件、句子和空白。

## 已完成流程

1. 结局分别读取 A/B 的选择历史、日记、私人物件、公共作品和玩法结果。
2. 饭店回声会重放玩家实际选择的三样材料。
3. 声音回声会重放真实排序，并区分可交付短轨与私人采样。
4. 代写回声会保留三句话的实际顺序，并区分保留声音、整理得过于清楚和快速成稿。
5. 错过预约会保留原日记文字；旧车站的两种处理也各有记录。
6. A 面对认可撤回时选择重新询问或安排下一次见面，会进入关系修复回声。
7. 结局按优先级显示最多五条，并限制同一类别只占一条，避免同类记录淹没其他经历。

## 数据入口

- 回声文案、条件、类别和优先级：`data/story/endings.json`。
- 状态匹配与占位符替换：`scripts/core/ending_echo_resolver.gd`。
- 结局排版：`scripts/ui/ending.gd`。
- 数据引用校验：`scripts/tests/content_validation_test.gd`。
- 动态内容回归：`scripts/tests/system_smoke_test.gd`。

正式对白进入项目时，可以只替换回声 `text`。稳定的模块 ID、选择 ID、日记 ID、作品 ID 和占位符不要改变。

## 下一步

为第五日翻译委托补一段专属双人场景和后续回响，让玩家实际保留的多重含义进入居民回应；随后再把棋局从通用选择板升级为可读的局面叙事。
