# 第五阶段：第二天饭店切片

## 目标

把第二天A线的饭店工作从一次菜单选择，扩展为“接受真实时段—协作备料—完成出餐—共同收台—获得认可”的完整劳动经历。正式菜品、美术与对白仍可以独立替换。

## 可玩流程

1. A在夜市原本只想买材料，遇见正在处理订单的饭店店主。
2. 逐拍入场场景先确认她能留下多久，以及此刻真正缺少什么帮助。
3. 烹饪工作台要求玩家按顺序挑选三样剩余材料。
4. 每增加一样材料，底部反馈会显示其他人如何同步腾出餐口、送回碗和报桌号，让选材发生在共同劳动里。
5. 玩家决定临时组合新菜，或先核对成本完成稳定菜单。
6. 返回小镇后，新增“把最后的台面收完”事件。店主在关火与收台以后签下认可。

## 数据与替换入口

- 入场与收台对白：`data/story/events.json` 中的 `a_d2_restaurant_shift`、`a_d2_restaurant_close`。
- 材料、过程反馈、结果和角色关系：`data/gameplay/module_prototypes.json` 的 `cooking`。
- 场景背景：`art/locations/night_market/night_market_restaurant_shift_v01.png`。
- 通用过程反馈显示：`scripts/ui/module_workbench.gd` 读取 `interaction.progress_steps`。

保持事件 ID、选择 ID、材料 token ID 和 `cooking` 模块 ID 不变，即可直接更换正式菜品、台词、背景、材料图标与声音。

## 当前叙事判断

店主的认可依据被明确为“忙乱时可靠补位，并在关火以后仍完成收尾”。菜做得新颖或成本核对得准确会留下不同关系记忆，但都不是把认可按钮化的捷径。
