# 第一阶段交付说明

## 已验证的玩家循环

1. 在主菜单选择 A 或 B。
2. 阅读各自不同的初始情报和可行动时间。
3. 选择地点和交通方式，承担时间与金钱成本。
4. 根据当前时间查询在场居民，或通过地点行动收集线索。
5. 在第 1 天 18:00—20:00 于河岸公园找到夏透明。
6. 完成对话，居民确认从 3 / 12 变为 4 / 12，并自动保存。

这条循环同时验证了提案最核心的四项结构：同一日双视角、连续/碎片时间、居民日程、信息影响路线。

## A 与 B 的差异

| 维度 | A | B |
| --- | --- | --- |
| 时间 | 14:00—21:00 连续可用 | 四段碎片时间 |
| 初始资金 | 180 元 | 45 元 |
| 信息呈现 | 随身记忆，强调偶遇结果 | 计划本，明确时间块和日程 |
| 特有路径 | 夜市拼桌获得方向线索 | 19:00—20:00 可搭朋友顺风车 |

## 视觉实现原则

- 不是给普通界面换成深色，而是把小镇做成不连续的剧场空间。
- 建筑由少量大平面和断裂轮廓构成；不追求写实街道的完整连续性。
- 人物后续采用低多边形剪影、弱面部细节、姿态和灯光先于表情。
- 黑色留白是构图的一部分；暖琥珀用于行动/当前状态，冷青色用于信息/计划。
- 塔拉牌桌保留用户参考图的交互层级：固定工作台、中央可操作对象、右侧信息、底部工具；具体资产与构图保持原创。

## 文本与美术接入约定

- 地点、居民、事件、案件使用稳定英文 ID；中文展示文本可直接替换。
- NPC 日程以分钟表示，例如 18:00 为 1080。
- 人物美术先交付正侧背三视图、身高比例、主色与识别性道具。
- 场景美术优先交付灯光构图图和模块平面，而不是先做高精度完整街区。
- UI 美术优先交付按钮九宫格、面板纹理、字体规范和图标表。
- 新剧情先写成“触发条件—花费—结果—新增事实—关系变化”，再填对白。

## 下一阶段进入条件

- 确定第一天的正式文本，以及 A/B 各自至少一条完整差异路线。
- 确定夏透明、Mossner 和 3—5 位关键居民的外形设定。
- 确定首个扩展玩法模块；建议在烹饪、代写、翻译中只选一个先做。
- 确定使用 3D 低多边形人物与场景，或 2.5D 分层剪影方案。

在这些内容未确定前，继续堆满全部玩法会制造大量返工；目前代码已经把可替换的数据入口和场景边界留好。
