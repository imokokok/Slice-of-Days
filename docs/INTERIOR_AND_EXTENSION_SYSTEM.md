# Solmere 室内与扩展玩法系统

## 玩家路径

统一交互链为：

`小镇横版/地图 → 建筑正面 → 室内横版舞台 → 物件热点 → 近景或扩展玩法 → 结果写回 → 原室内`

玩家抵达对应地点后，行动栏显示室内入口。进入室内不会自动扣时；和居民对话消耗 20 分钟，扩展玩法只在完整完成时结算其规定耗时，取消不会吞掉结果或把玩家送到错误地点。

## 九个室内

配置位于 `data/world/interactive_spaces.json`：

- 潮汐饭店：烹饪工作台、听懂你。
- 塔罗店：完整塔罗海龟汤。
- 潮声唱片：声音授权工作台、完整 Town Sound 唱片工坊。
- 海盐书信事务所：拼贴书信。
- 河岸棋社：老棋友。
- 夜海观景台：星图观察。
- 余光照相馆：摄影工作台。
- 旧车站候车厅：空间错觉工作台。
- Solmere公共档案室：来源核对与交叉索引。

室内统一使用奶油纸、陶土色、灰蓝和低饱和海色界面。第三张参考图只采用“场景内舞台 + 说话人 + 大字幕框”的信息关系，没有沿用其冷色低多边形画风。

## 原生生活玩法

`scenes/native_module_game.tscn` 根据稳定模块 ID 提供五套不同操作，而不是只显示选择卡：

- 烹饪：按顺序选择三样材料，将火候保持在稳定区后决定临时新菜或稳定菜单。
- 声音授权：把三段素材排入时间线并完整试听；未授权人声和无来源片段不能进入交付路线。
- 摄影：选择两到三处画面关系，调整曝光避免高光/暗部丢失，再按下快门。
- 空间错觉：同时保留两份矛盾记录，旋转观察角度直到门、楼梯和光线在同一投影中重合。
- 公共档案：展开三份照片、票据、时刻或声音记录，保留来源后建立可复查索引，或明确标出证据缺口。

每次操作都将素材顺序和火候、曝光、视角或试听状态存入玩法结果，因此后续对白和结局仍能读取玩家实际做过的事情。

## 扩展协议

`data/gameplay/modules.json` 为每个可接入扩展声明：

- `scene_path`：统一宿主场景。
- `extension_scene_path`：扩展自身入口。
- `completion_hint`：宿主栏的完成条件说明。
- `direct_time_minutes`：从室内直接游玩时的耗时。
- `external_results`：回写的事实、日记和作品。

`scripts/ui/extension_host.gd` 负责加载、适配尺寸、观察完成条件、取消、结算和返回。扩展不需要直接依赖主游戏事件文件；主游戏也不需要复制扩展内部的交互实现。

当前完成条件：

- 听懂你：完整走完三段对话和六次记忆交换。
- 拼贴书信：完成拼贴、折叠、装封、火漆并送出。
- 老棋友：完成一局棋。
- 夜海观景台：发现并收藏至少一个星座。

## 状态边界

- A/B 的金钱、事实、日记、关系、玩法结果和 Studio 工程相互隔离。
- 明确标为共享的棋局或唱片作品进入 `world_artifacts`。
- 室内导航只存在于本次运行，不写入长期存档，避免读档或换视角后返回旧房间。
- 唱片付款以 `record_id` 建立共享去重账本，重试、重启或重复点击不会二次付款。
- 声音样本记录来源、角色、日期、时刻、地点、附近居民、关联事件和使用范围。麦克风以及含在场居民的素材默认 `local_only`。

## 单机与联网边界

录音、编曲、视觉、封面、压片、唱片架和主游戏结算均可离线完成。公共唱片库接口在未配置服务时明确返回 Local Mode，不发送网络请求。跨玩家发布还需要独立后端、对象存储、鉴权、举报/下架和隐私审核；这部分不能仅靠客户端安全地假装完成。

## 验证

- `scenes/content_validation_test.tscn` 校验所有室内、物件、模块、扩展场景和资源引用。
- `scenes/system_smoke_test.tscn` 校验外部玩法结算、主存档回写和唱片付款幂等。
- `tests/integration/test_interactive_spaces.gd` 实例化室内，并逐个实例化四个扩展入口。
- `tests/integration/test_native_modules.gd` 实际完成五个原生生活玩法并验证剧情结算。
- `tests/town_sound/` 覆盖录音、工程校验、四轨编排、视觉生成、相册和本地唱片流程。
