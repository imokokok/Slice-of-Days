# 第六阶段：第三天声音采样切片

## 目标

把声音工作从“排列三个素材”扩展为一段关于来源、授权、交付与私人记忆的完整体验。玩家仍然可以自由编排，但可交付结果不再接受任何组合。

## 叙事流程

1. B处理完工作打断后，在雨天把采样带到唱片店。
2. 唱片店声音师提醒她：同一份文件同时包含环境声、演奏和模糊谈话，不能把整份文件统一视为已经授权。
3. 阿锰明确同意使用公园演奏段，不同意使用之后的私人谈话。
4. B选择逐段标记来源，或先排除全部可辨认人声；两种做法都会留下不同的关系记忆。
5. 工作台要求排列三段声音，并持续显示当前处理阶段。
6. “完成可交付短曲”只允许已授权且来源可追溯的素材；含未授权谈话或无来源门轴声时，按钮会被禁用。
7. 私人漫游采样可以保留边界不明的片段，但不会作为交付版本，也不会获得阿锰的认可。
8. 合法短曲导出后，文件中出现原始波形不存在的旧门轴声。B可以保存私人副本，也可以删除声音、只保留文字记录。

## 机制入口

- 逐拍场景与异常分支：`data/story/events.json` 的 `b_d3_sound_session`、`b_d3_hinge_isolate`。
- 声音素材、过程反馈和交付约束：`data/gameplay/module_prototypes.json` 的 `sound_sampling`。
- 约束执行：`GameplayModuleSystem.choice_interaction_check()`。
- 工作台按钮状态与原因提示：`scripts/ui/module_workbench.gd`。
- 雨天唱片店背景：`art/locations/record_store/record_store_rain_session_v01.png`。

## 可替换范围

正式声音进入项目后，可以直接替换 token 展示名并增加音频路径。只需保持 `rain_awning`、`bus_brake`、`distant_flute`、`cafe_cups`、`old_hinge` 等稳定 ID，授权规则与旧存档结果不会失效。

门轴声目前只以文字和数据作品存在。后续可以增加本地音频播放，但建议等环境声音规范确定后再接入，避免临时素材被误当成最终声音设计。
