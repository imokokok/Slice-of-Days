# Residency V3 实装记录

## 审计发现

- 旧要求缺少生活小票数量、用途类别、认可生活圈限制。
- Explore 依赖 Day 2 自由文字和到访数量，无法区分三类观察，也缺少同地点跨时段凭据。
- 作品完成直接等同贡献，公开余波早于实际交付。
- 收据只包含简单支出，采购报销容易与收入证明混淆。
- 普通居民认可按接触次数判断，同一事件重复上报会重复计数。

## 运行时入口与依据

`F → 要求` 显示实际数值；每一行打开对应纸张。资料袋保留六份独立文件，作品集固定七页，A/B 各自存储。

| 要求 | 实际来源 | 归档与检验 |
|---|---|---|
| 收入证明 ×1 | GameState 实付正向流水 → 工资记录 → 对应营业柜台领取 | 玩家夹入档案后计入；初始资金与报销除外 |
| 生活小票 ≥3、用途 ≥2 | 商店或交通实际负向流水；EconomySystem 同源小票元数据 | 原始交易 ID、金额、有效标记和用途均需匹配；报销章更新同一原件 |
| Explore ×3 | F → 要求 → 三种实地探索 | “发现”“换时段回访”“愿意带别人去”分别保存；回访要求同地点两个真实时段；文字保持自由 |
| 认可 ≥12、生活圈 ≥4 | RelationshipSystem 正式授予的签记 | 同事件去重；普通居民认可参考不同接触事件；资料中的圈归属来自已知角色/作息地点 |
| Contribution ≥1 | 完成作品 → 柜台签收 / 真实公共投递 / 唱片入库 / 照片公开展示 | 公开世界中存在已接受记录后才可领证明；归档证明计入；次日出现对应回应 |

文件仅表示玩家选择如何归档。收据、观察、签记与证明各保留来源和内容；TODAY / RECORD、Day 5 与 Day 7 仍自由书写。

夜间在自己房间打开整理桌，可把签记拖入 Recognition 或当天页面。最多七天、每日最多两处签记；认可页可单独保留签记。

照片只在已冲洗状态进入素材本与相册。照片详情接 FilmSystem 的展示/拼贴入口，夹入档案时同步 `submitted_to_dossier`。

## 贡献保存

创建阶段保留个人作品记录。真实接受后记录 `contribution_entered_town`、接受地点/日期/凭据及唯一 `world_trace_id`，写入原有 `shared_state.world_artifacts.contributions` 与 `visible_echoes`。重新读档、重复交付或重复领证明均复用唯一来源。

厨房跨关门完成班次，仅在真实采购单已经 completed / accepted / paid / placed_contribution 且作品对应当前出餐结果时允许签收；证明仍按营业时间领取。

声音作品须走既有制片入库流程。普通作品柜台不能把未入库的声音草稿直接变成唱片贡献。
