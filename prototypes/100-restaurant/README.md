# 100饭店

可接入大游戏的 Godot 4.7.2 / GDScript / 2D 自由烹饪小游戏。窗口采用白天暖色厨房，食材、器具、人物使用重新绘制的独立素材。当前为可玩的开发版本。

## 开始游玩

运行 Windows 试玩包中的 AfterHoursKitchen.exe；名字保留用于兼容旧启动路径，窗口标题为「100饭店」。源码用 Godot 4.7.2 Standard 导入 project.godot，按 F5。欢迎页可开始营业或练习。

## 鼠标操作

| 对象 | 实际操作 |
| --- | --- |
| 冰箱、台面食材、奇异材料架 | 按住材料拖到台面、菜板或锅中，松开放下；取得的是完整材料 |
| 打开全部食材 | 搜索和分类选择全部当前可用材料；常用材料分区陈列，避免挤满场景 |
| 奇物箱 | 点击取一件可用物品；九件一轮不重复，下一轮首件不重复上一件，手中已有东西时不会消耗抽取 |
| 主厨刀 | 按住右侧刀柄，让刀刃划过菜板上的食材，生成两个真实切块；松手停止跟随。拖任一切块可整批入锅，各块仍独立受热和碰撞 |
| 三把厨具 | 木铲、木勺、黑锅铲都能拿起。铲头碰到食材才推动；木勺有三段物理勺沿，食物显示在勺底和前沿之间，轻移可承托，快速甩动或滚轮倾勺会滑出 |
| 锅 | 拖锅柄自由移动，松手落台；按住右键倾倒或用滚轮调角，让食物从锅口实际落下 |
| 水槽 | 按住右侧水龙头把手向下转开、向上回转关闭；把锅移至水流下接水，可以倾锅倒水，回到灶台再加热 |
| 小火 / 中火 / 大火 / 关火 | 控制真实受热速度；各材料独立记录熟度和焦糊 |
| 调料 | 拿起容器后在锅上方按住鼠标，按类型撒粉、倒液体或挤酱；松手停止，容器本身不进入配方 |
| 溢出的污渍 | 空手点击擦掉；持续挤酱会溢出，溢出部分不算入料理 |
| 盘子 | 拖动会带着已装盘食物一起移动；单击打开较小的摆盘页 |
| 摆盘页 | 同一次切出的整组食物或全部食物可一次装盘，再自由移动旋转、淋酱、拍照；也能保留火候回锅 |
| 聊聊口味 | 向当前客人了解偏好；实际影响备料选择 |
| 出餐 | 只有实际装进盘子的完整料理才能交付；评价食材、切配、火候和口味，显示餐费、小费或赔偿 |
| 丢弃 / 清理台面 | 手中有材料时丢弃该材料，空手时清理锅、盘、散落材料和洒漏 |

没有放大菜板：切菜直接在右侧台面完成。底部操作提示有独立区域，不覆盖厨房。键盘快捷键是可选辅助；Q 放下、TAB 食材、J 菜谱、P 海报、ESC 暂停。

## 经营和食材

- 数据库含 88 种材料定义；按“无鱼”规则，鱼和三文鱼不进入取材与点单池，当前可用 86 种。物件具有质量、摩擦、受控碰撞和口味标签。
- 前景陈列 40 个常用取材入口，其余通过食材柜选择。奇物箱提供棒球棍、鼠标、拖鞋、袜子、香水、玩偶、口红、橡皮鸭和石头。
- 一锅最多容纳 6 份来源食材、合计 48 个物理切块。只有实际落入锅里的材料才计入料理；同源切块独立记录几何、物理身份和受热，切割守恒质量，每个分支最多细切四次。
- 各食材分别受热，小中大火速度不同；生食、熟食、烧焦根据不同客人口味评价。焦叔偏爱焦香，但其他客人可能不喜欢。
- 客人统一等待 120 秒。菜谱、海报、摆盘和暂停界面打开时，小游戏计时与受热暂停。正式班次默认 4 分钟。
- 评分低于 20 分不收餐费并扣赔偿；20–80 分按分数收取餐费；高于 80 分另有金额不等的小费。结算明确列出三项金额。
- 9 个顾客档案，其中 8 位可到访；角色各有称呼、习惯、偏好、忌口、评价和离开台词。
- 翻炒接触声按湿软蔬果、肉和海鲜、干燥谷物、硬质奇物分别播放，木勺略低沉；只在厨具实际碰到食物时触发。其余合成拟音对应切菜、落物、调料、点火、炉火、水流和沸水。不是实地录音。

## DIY 菜谱和海报

新建作品是一张完全空白的纸。纸外列出当前料理实际用料；锅空时可使用上一道料理，也可以不做菜直接创作。

素材由玩家主动加入：文字、食材、料理照片、导入照片、贴纸和胶带。支持移动、旋转、缩放、复制、删除、图层调整、自由画笔与多边形裁剪。胶带还能改变颜色、独立长宽，并拖动端点拉长；撤销和保存会保留设置。

摆盘照片只拍餐盘，不含界面或选中框，PNG 为 640×357；拍照后由玩家决定是否放进菜谱。已有菜谱可继续编辑、保存修改或另存新作品。作品通过本地 JSON 导出、导入和分享，尚未连接网络服务。

海报保存和发布给宿主的事件保留，厨房内不再挂作品预览；后续由大游戏安排室外展示。

## 接入和维护

完整复制 modules/restaurant/，实例化 restaurant.tscn。入口、信号、存档及独立视口约定见 [接入说明](docs/INTEGRATION.md)。小游戏不直接修改主游戏钱包。宿主接收有符号的结算分成：收益可正、赔偿可负，不能把负值当作无效数据丢弃。

虚拟视口为 1600×946，其中厨房区域高 900，最下方 46 像素用于说明。美术来源和图层约定见 [场景素材说明](docs/SCENE_ART.md)。完整改造规格、逐项台账与实际验证分别见 [完整规格](docs/COOKING_FULL_SPEC.md)、[180 项台账](docs/COOKING_ACCEPTANCE.md)和[验证记录](docs/VALIDATION.md)。

## 当前边界

这是 2D 刚体模拟，不是完整 Cooking Simulator：没有三维网格切割、连续局部流体、软体、烤箱、搅拌机或多盘多锅系统。酱汁以 ml 批次记录组分、来源、容器余量、转移和残留，视觉混色明确属于近似。未完成设备不作为可点击道具放进场景。背景建筑、窗外街景和灯光属于环境。

大游戏工程尚未提供，因此保留模块接入接口，但未宣称已完成主工程集成。主世界日程、在线菜谱和永久存档钱包由宿主接入。
