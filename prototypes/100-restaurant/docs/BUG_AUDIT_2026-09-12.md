# 100饭店缺陷审计（2026-09-12）

审计范围包括当前 Godot 4.7.2 源码、食材与容器状态、锅和工具物理、装盘、摄影、DIY 菜谱、顾客、结算、音频、存档和默认回归入口。自动化使用实际场景树、鼠标事件、2D 刚体和 GPU 捕获；当前自动化接口不能读取已打开的原生 Godot 窗口，因此没有把桌面人工点击声称为已验证。

## 已实现并验证

| 优先级 | 原问题 | 修复与证据 |
| --- | --- | --- |
| P0 | 锅中食物没有装盘也可直接点击“出餐”结算 | 出餐现在要求存在实际 `plated` 实体，并拒绝任何未装盘的已登记食物；集成回归覆盖拒绝与成功两条路径。 |
| P0 | 倾锅只倒出固体，500 ml 水在 110° 时仍留在锅中 | 越过锅沿角度后扣除锅内水；在水槽上方排入下水，在台面上生成带体积的可擦水渍。 |
| P1 | 24 项菜谱上限小于 48 块厨房容量，合法切块无法保存 | 菜谱、重载与便携导入统一到 48 块；第 49 块仍触发明确上限。 |
| P1 | 大量切块只能逐个点击装盘 | 按来源批次生成装盘入口，并提供全盘一次装入；每块仍保留独立几何与状态。 |
| P1 | “丢弃／清台”实际只清锅中登记物，散落物和溢出状态残留 | 改为“丢弃／清理台面”，空手触发时清理锅、盘、松散食物、调料和水渍。 |
| P1 | DIY 的“拍摄料理”会截取整间厨房，而不是盘中成品 | 只有来自实际摆盘画布且版本未变的照片可以加入；否则明确引导先到装盘台拍摄。 |
| P2 | 高拟真状态测试存在但未加入完整测试脚本 | 已加入 `tools/test.ps1`，默认回归会检查面条热水软化、酱汁组成和连续状态。 |

本轮完整结果：20 个带计数测试共 1442 项通过；存储和海报烟雾测试通过；88 个食材图形透明底审计为 0 错误；GPU 摆盘捕获通过。

## 近似实现

- 水从锅中流出目前以越过锅沿后的守恒转移处理，落到台面形成二维体积水渍；没有连续液面网格、逐滴流线或不同容器间的流体重采样。
- 锅、食物与工具使用 Godot 2D 刚体、限速和分层遮挡；不等同于连续三维碰撞或软体模拟。
- 翻炒、落物、水流、沸腾和工具声音使用程序生成的分类拟音。触发条件和停止条件经过测试，音色没有通过实地录音素材验收。
- 酱汁保存毫升、来源、组分、混合度和残留；视觉颜色为校准前的二维加权近似。

## 尚未实现／需要方向确认

- 最高层规格要求完整厨房中存在玩家位置、交互距离和 WASD 移动；当前版本仍是固定第一人称台面，远处取材通过可点击陈列和食材柜完成。
- 普通食材来源没有有限库存与补货记录；同一入口可以重复取用。奇物箱只有轮次不重复规则，不是经营库存。
- 顾客回复会保存并可继续编辑，但尚未进入后续 NPC 对话或关系变化。
- 当前只有一口平底锅、一只餐盘；没有多锅、多盘、烤箱、搅拌机和跨容器连续液体系统。

上述项目没有按钮伪装为完成。是否重建 WASD 完整厨房会改变当前固定台面构图和主要输入，因此应由产品方向明确后再实施。
