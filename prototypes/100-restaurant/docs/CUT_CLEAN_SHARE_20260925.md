# 切配、清锅与 DIY 菜谱分享

本轮按 Little Chef 的物件交互、Venba 的纸面菜谱、Cooking Simulator 的操作反馈分工更新，保留用户确认的二维厨房布局。

## 实际交付

- 生成并接入番茄、洋葱、胡萝卜、土豆、蘑菇、茄子、浅绿瓜共 **7 类 × 6 种切面 = 42 个变化**，每类含 3 种片状、3 种块状。另有甜椒 6 个备用变化，尚未在目录建立对应物品，不能计入可玩食材。
- 刀线继续裁切实际多边形；切掉 1/5 或 2/5 由真实落刀位置决定，剩余外形和质量随切割改变，不用一组整食物图片假装切割。平行切保持片状，交叉切转块状；生成图只补充内部切面。
- 切下的食物会短暂落下、偏转、滑动并通过摩擦停在固定菜板范围内；打开菜谱时暂停，拿取时退出落板状态。入锅后继续使用既有二维刚体系统。
- 抹布现在可拿起：**先关火并装盘 → 水龙头下打湿 → 按住拖过空锅底 → 放手归位**。必须实际接触、移动才擦除残留；抹布会变脏，冲洗后脏物进排水记录。
- 做过菜的锅有有限量残留，离锅食物失去的这部分质量进入锅膜；下一道食物会带走部分残留，并实际影响口味标签和顾客评价。单纯清理台面不会自动洗锅。
- 已保存的 DIY 菜谱有“分享这一页”：导出一个自包含 HTML，朋友无需游戏即可查看纸页、完整叮嘱、做法及已有成品照；页底下载附带的单道可编辑 JSON，导入游戏后可继续绘画、修改和跟做。也可直接导出这一道 JSON，不会连带其他私人菜谱。
- 纸页、台面菜谱架和分享图共用渲染器；玩家的原始文字、画笔、拼贴与照片仍然可编辑。

## 发现并修复的问题

| 问题 | 修复与验证 |
| --- | --- |
| 切块不自然地停在原位 | 加入落板高度、速度、转动和摩擦，并测量刀后位移、转角与最终静止；暂停时不推进 |
| 分切后两块都保留整份表面酱汁 | 按子块面积比例分配 ml、成分及上锅残味；连续交叉切检查质量、酱量守恒 |
| 菜谱切配示意中其他食材变成番茄 | 不再用丢失脚本属性的 Node.duplicate；明确重建食材身份、切面、熟度与软度，增加洋葱回归 |
| 静态背景里的毛巾无法使用 | 仅覆盖其局部背景区域，保留其他布局，加入真正可操作抹布 |
| 无清锅与串味之间的因果关系 | 建立食物 → 锅残留 → 下道食物 / 抹布 → 排水的有限量传递 |
| 分享必须连同整本菜谱导出 | 增加单页导出与离线阅读文件；确认不会包含第二份私人菜谱 |
| 分享文本可能被当成 HTML 执行 | 转义用户标题、署名、叮嘱，限制外部内容；恶意标签用例及附件重新导入通过 |
| 帮助页及旧测试的材料数量过时 | 帮助按当前目录计算：97 个定义，95 个可用；继续排除两种鱼 |

## 明确边界

**近似实现**：这是二维支撑面上的重力、滑动与转动模型，没有三维厚度网格、软体组织或逐粒流体求解。残味按有限质量和食材标签计算，不是化学模型。抹布没有织物折叠、任意表面污渍吸附和焦垢硬度模拟。不能称为“绝对仿真”。

**尚未实现**：所有 95 种可用物品的专属切面；甜椒对应可玩条目；在线公开菜谱社区、账号同步。分享页需要作者主动发送文件，不会自动上传。做法仍按成品状态整理，不是精确的逐步历史回放；作者可在纸面文字中补充具体顺序。

**原作接入限制仍存在**：19 张透明手绘 PNG 已接入且未修改；13 张黑底 JPEG 和番茄白底 JPEG 保留原件，未冒充已完成透明原作替换。本轮新增切面明确是用户授权的生成派生图。普通整件与派生切面在部分品种上的色调还需要统一美术验收。

**已实现但未完成人工验收**：系统鼠标从营业到连续多客人的长时间乱操作、逐条人耳试听、各机型窗口缩放兼容；自动化和 GPU 截图不能替代这些验收。

第三方筛选结果见 [素材与代码检索](ASSET_RESEARCH_20260925.md)，Little Chef 素材页禁止原始素材再分发，因此没有把该包放进公开源码。
