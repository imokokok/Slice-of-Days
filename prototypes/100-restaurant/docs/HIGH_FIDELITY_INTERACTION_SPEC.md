# 2D 饭店小游戏：高仿真交互改造专项规格

本文件记录 2026-09-09 提交给 `100饭店` 的完整改造要求，是实现前必须阅读的专项规格。工程保持 Godot 4.7.2、第一人称固定视角和可嵌入 `modules/restaurant` 的结构；不得另建脱离工程的演示项目。

## 1. 不可破坏的产品约束

1. 全流程使用同一套几何构成、有限暖色和少量手绘感的原创 2D 画风。原料、切块、锅内食物、酱汁、装盘、照片和菜单不得切换成 3D、写实照片、透明棋盘底或边缘粗糙的抠图。
2. 场景里出现且看起来能操作的厨具、容器和工作位必须真的可用；未实现的设备不进入可交互层。禁止用按钮、图标和说明文字伪装尚未实现的功能。
3. 食材使用一条连续状态链：完整原料 → 实际几何切块 → 容器内实体 → 受热/焦化 → 沾附酱汁 → 实际摆盘 → 由当前餐盘渲染的照片 → 菜谱记录。不得在任一步骤替换成预制成品图。
4. 正常烹饪和故意乱做都要产生可见结果、可追溯状态和相应顾客反馈。经营结算、小镇接入信号和负收益语义保持兼容。
5. 当前可选材料和点单池不放鱼类。旧存档中的鱼类标识允许只读兼容，但不得主动陈列或生成。

## 2. 食材、容器与工具状态

### 2.1 食材连续性

- 每个实体有稳定实例标识、原始材料标识、质量、几何轮廓、切割谱系、火候、焦化、表面酱汁组成与数量、所在容器和摆盘变换。
- 切割必须改变碰撞与绘制使用的实际多边形，并满足质量守恒；生成的分块沿用父块的火候和表面酱汁比例。
- 工作区切换和近景只改变视图与操作比例，不复制、重置或替换实体。

### 2.2 勺与铲

- 铲子的平面工作面负责推、翻和刮，承载能力低；拿起时保持斜向姿态。
- 勺子由凹形工作面和两侧边界形成实际盛取区，可盛食物和酱汁；倾斜后按重力和开口方向流出，并保留少量残留。
- 两者使用不同接触范围、角度、摩擦/回弹近似和声音。声音只在实际接触时触发，并按食材材质分类。
- 数量必须有来源和去向：锅/盘减少多少，勺腔增加多少；倾倒时相反；残留量独立记录。

### 2.3 挤酱与混合

- 挤酱为持续按住输入。一个 `pressure` 状态同时控制瓶身局部压缩、喷口位置、单位时间流量和循环声音；松开后压力回落并停止流出。
- 鼠标轨迹和压力共同形成点、线和局部堆积。持续挤压超过容器/表面容量会真实溢出，溢出不计入菜品。
- 每批液体记录来源容器、总体积、组成体积、黏度、颜色近似、混合程度和可选分层。未搅拌、逐渐混合和稳定分层有不同画面。
- 当前颜色和流动只允许标为视觉/二维物理近似；禁止把 RGB 平均称为真实混色或完整流体模拟。

## 3. 厨房流程与近景

- 玩家能在同一个持续世界中移动到冰箱、柜子、篮子、备菜、烹饪、摆盘和菜谱区。移动与工作位近景不得重建会话或复制物品。
- 食材从冰箱、柜子或篮子中取出时保持完整，玩家自行切割。
- 近景用于放大实际实体和精细操作。菜板不使用独立的假放大弹窗；切菜在当前持续场景中完成。
- 餐盘单击进入较小摆盘近景；盘子本身和盘上食物可拖动。摆盘支持实际食物位置/旋转、淋酱和拍照。
- 锅可自由拖拽、倾倒；水槽只有转动水龙头把手后出水，水可进入锅并被倒出。

## 4. 菜谱、照片与菜单

- 新菜谱从完全空白纸开始，纸外显示当前菜品实际用料；素材由玩家主动加入。
- 可拍摄当前实际餐盘、命名、署名、拼贴、绘制、贴纸、胶带、保存和继续编辑。胶带与贴纸支持移动、旋转和缩放；胶带另支持颜色与长宽。
- 照片必须由当前餐盘状态渲染，不得替换为预制菜图。保存的菜谱包含菜品状态快照和编辑数据。
- 已保存且启用的菜谱进入实际营业菜单，顾客可以点单；评价须比较本次出餐与所点菜谱，而不是只显示收藏品。
- 宣传海报功能保留，发布结果交给宿主在店外展示；厨房内不挂海报预览。

## 5. 顾客、反馈和经营

- 顾客有稳定人物特征、偏好、忌口、说话方式、当天经历和过去经历；交谈内容与评价相互呼应。
- 点单前显示餐前心情，结算后显示餐后心情及数值变化。表情使用原创简约 2D 绘制，不用系统 emoji，不画恐怖或怪异表情。
- 顾客对实际材料、切配、火候、焦化、酱汁、摆盘以及与菜单目标的匹配度给出较完整、具有角色口吻的评价。
- 等待上限为 120 秒。低于 20 分不收餐费并扣赔偿；20–80 分按表现收餐费；高于 80 分获得金额不等的小费。

## 6. 声音

- 点火、稳定火焰、沸水、水龙头、切割、食材落台/落锅、挤压、流出、搅拌、翻炒、铲刮、盛取、倾倒、装盘和出餐均由实际状态触发。
- 接触音按湿软蔬果、肉类、干燥谷物和硬质奇物区分，并受工具材质、速度和接触强度影响。
- 合成或程序占位拟音必须在交付状态中明确列为近似；未取得真实拟音素材不得宣称完成真实拟音。

## 7. 实施阶段

1. **纵向代表流程**：番茄/肉块切割连续性；可移动锅；持续挤酱；勺腔盛取/倾倒；摆盘和实际照片；顾客评价与结算。
2. **工作位连续世界**：厨房移动与近景；冰箱/柜子/篮子取物；跨工作位状态持久。
3. **菜谱进入营业菜单**：保存、继续编辑、启用、点单与匹配评价。
4. **顾客叙事与心情**：当天/过去经历、餐前餐后图标与变化量、角色化反馈。
5. **扩展材料和声音**：在代表流程稳定后扩充材料适配与真实拟音素材。

## 8. 验收清单

- [ ] 实际运行 `project.godot` 或导出包，窗口可完成一次营业流程。
- [ ] 完整食材切成不同形状后，锅内、盘内和照片保持这些形状。
- [ ] 连续按住挤酱产生可变长度/厚度轨迹；松开立即停止；记录体积来源、去向和溢出。
- [ ] 勺子能实际获得、携带、倾倒酱汁并保留残留；铲子不能获得同等盛液能力。
- [ ] 未混酱汁、搅拌中酱汁和分层近似有可见区别，并在界面/文档标明近似。
- [ ] 工作位移动与近景前后，实体数量、实例标识、质量、火候和酱汁不变。
- [ ] 当前餐盘照片与实际摆盘一致；菜谱可保存、继续编辑并进入顾客点单池。
- [ ] 顾客显示原创心情图标、餐前/餐后值和变化量，并能谈当天或过去经历。
- [ ] 主动材料池无鱼；旧存档鱼类数据不会导致崩溃。
- [ ] 交互回归测试、领域测试、集成测试和无界面启动均通过，且输出中无脚本错误。

## 9. 交付状态口径

- **已实现并验证**：代码已进入当前工程，并经过对应自动化测试及实际运行检查。
- **已实现但未验证**：代码已进入当前工程，但缺少要求的运行环境、素材或人工操作证据。
- **近似实现**：交互闭环存在，但二维物理、颜色、声音或视觉模型不是现实级模拟；必须说明近似点。
- **尚未实现**：没有有效入口或没有真实状态变化。不可用占位按钮不得保留在可玩界面。

每次修改前先阅读本文件相关章节；每次交付更新 `docs/VALIDATION.md`，按上述四类列出结果，并单列缺失的真实拟音和美术素材。
