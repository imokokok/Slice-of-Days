# 锅内热变化、附着与相变：实现和问题报告

后续更新：原报告中列为缺口的鸡蛋破壳已补上两次锅沿敲击、裂纹、蛋液下落及有质量/来源记录的壳片。实现与验证见 [当前进度](COOKING_PROGRESS.md) 和 [敲壳录像](qa/20260925-egg-cracking.mp4)；下文“尚未实现”保留的是本报告当时的历史状态。

本轮把锅温、食材表面/内部温度、含水量、两面焦色、软化、液相、附着酱汁和录音触发接到同一份持续状态。保留当前二维厨房、团队原画、固定菜板、实体切割及原有物性响应；不是更换画面或只在计时结束时换成品图。

## 发现并修复

| 原问题 | 现在的行为 |
| --- | --- |
| 食材主要靠统一加热秒数改变颜色，切薄和整块受热差异不足 | 锅先升温，再传热给接触面和内部；质量、材质和切后比例影响传热，薄片内部升温更快 |
| 沸水中持续计时也可能判为焦糊 | 湿热与干煎分开；水浴受热不会新增长焦色，原来烧焦的历史也不会被加水清除 |
| 关火立即失去烹饪反馈 | 锅保留余热，逐渐冷却；食材、泡沫与录音随实际温度衰减，界面提示余热 |
| 表面有酱汁数据，但视觉没有按它着色 | 番茄酱局部红色覆盖，酱油较薄的棕色染色，油膜反光，盐/胡椒细点；翻拌逐渐摊开附着层 |
| 酱汁转移没有同步刚体质量；木勺使用统一密度 | 原容器/酱体实际减量减重，目标增重；木勺保留所舀混合物质量，按真实余量比例转移 |
| 混合超过八种成分会丢量，反复转移舍入误差，黏度忽略比例 | 保留全部组分，去掉逐步舍入，黏度按实际体积加权 |
| 受热物体基本仍是原形，没有有限固态转液态 | 黄油、芝士、巧克力、冰淇淋有不同阈值/潜热近似；软熟番茄在翻拌后逐步出汁；液相来自原件质量，不生成无限副本 |
| 煮面吸水不从锅中扣水，蒸发缺少有限账本 | 米/面/面包吸水增重并扣锅水；食材和锅水蒸发独立记账，食材蒸发实际减重 |
| 录音依赖开火/计时，水刚到阈值时启停生硬 | 水温 92–100 的连续强度同时控制细泡/沸腾与录音；湿锅不同时干煎，干净油和完全无水食物不凭空发出水汽滋响 |
| 着色和热状态在 DIY 食材贴纸中丢失 | 摆盘、切片、做法示意和可编辑贴纸保留状态；磁盘保存/重开验证；损坏的温度数组或酱汁坐标在导入时拒绝 |
| 新状态使用 GDScript StringName 字段时保存被误拒，JSON 重开后整数变浮点被误拒 | 接受 JSON 可表示的字符串键和整数值；保留原有路径、脚本、非有限数及尺寸限制 |
| 引擎脚本报错后某些测试仍可能退出 0 | 测试入口同时检查错误输出和成功标记，不能仅以退出码判通过 |
| 完全被吸附的酱汁仍可能作为空份留在装盘/配方中 | 转移完后移除旧实体和配方条目，附着层继续保留实际质量与组分 |
| 表面焦黄的生心食材可能借表面热量获得较高熟度分 | 未熟品质只读取核心熟度，不再借表面褐变抬分 |

## 行为与交接

- `domain/food_thermal.gd`：两面与核心三节点热模型，有限热交换、蒸发、熟度、干热褐变/焦化、软化和有限相变。翻起时更换接触面，不清掉另一面历史。切块分配质量、含水量、液相和附着量，保留温度与颜色历史。
- `world/cooking_reactions.gd`：唯一固定物理步更新者。锅热容量、炉火功率、散热、水温、吸水、相邻食材润湿及液滴路径命中在这里更新。旧 session 熟度计时仅为不带实体的旧域接口保留；已有 thermal 的实体不会被两次加热。
- `food_body.gd` / `material_response.gd`：受热形状包络与碰撞一起变，软化/液相降低回弹并增加阻尼；实际平移、旋转、碰撞仍由 Godot 刚体求解。
- `cooking_surface.gdshader`：在原食材纹理上做稳定局部附着、薄酱染色、接触焦色与油光。部分液化时原件缩小、同源液相展开，不替换成预制菜品。
- `kitchen_audio.gd`：继续用 35 条外部 CC0 录音、49 个片段、32 组；本轮没有新合成声音，也没有新增未知许可依赖。
- `food_snapshot.gd`：验证新嵌套热/表面记录；旧无此字段的菜谱继续读取。分享仅传状态，不加载脚本或外部资源。

参数经过游戏节奏校准且时间压缩，不是食物安全温度指南或实验数据。热量与潜热概念参考 [OpenStax 热传递](https://openstax.org/books/college-physics/pages/14-section-summary) 和 [相变](https://openstax.org/books/physics/pages/11-3-phase-change-and-latent-heat)；这里没有实现教材中的完整连续介质场。

## 开源使用

继续使用 [Godot 原生 RigidBody2D](https://docs.godotengine.org/en/latest/classes/class_rigidbody2d.html) 和已锁定的 [MIT GodotSpringDamper](https://github.com/Hyphinett/GodotSpringDamper) `0da23b9b6c82af5a4d2605671f503a9c2aaa239e`。版权/许可保留在第三方目录并进入 Windows 导出。弹簧处理受压与晃动，不冒称液体引擎。本轮没有把另一个刚体引擎叠到 Godot 上；此前 Rapier/Salva 与现有非对称遮挡/碰撞分层适配的取舍仍见 `MATERIAL_PHYSICS_20260925.md`。

## 验证方法与证据

`tests/test_thermal_reactions.gd` 检查尺寸/材质差异、核心与表面温差、水煮不焦、有限相变、惰性奇物、冷却历史、两种步长和组分守恒。`test_reaction_kitchen.gd` 在生产场景验证落锅、实际质量转移、酱色、翻面、余热、暂停、煮水、装盘、切割、融化润湿、DIY/磁盘重开以及损坏分享数据。旧热测试改为推进实际锅温，不能直接增加一个秒数跳过物理。

GPU 图与日志放在 `qa/20260925-thermal-reactions/`。`progression.png` 使用生产状态模型和渲染器排列五类食材的演变；不是玩家操作录像。厨房测试为可重复比较而把部分实体放在受控位置并推进物理状态，实际刀/铲/拖拽输入仍由原有回归覆盖。混音试听由实际 Godot 音频总线捕获，状态由测试脚本设置，不冒充人耳验收。完整当次结果见 `VALIDATION.md`。

## 当前边界

**已实现并验证**：上述有限状态、不同材质的热/声/色/形响应、实际刚体质量转移、存档与旧流程回归。场景图只代表已查看的状态。

**近似实现**：二维刚体与形状包络；三节点温度及时间压缩；按邻近半径/液滴路径传递酱汁；加权颜料覆盖；熔融物仍是有质量的薄层刚体，不能自由流过任意缝隙；番茄出汁是有限参数模型。不是三维柔体、CFD、分子化学或实验标定的烹饪模拟器。

**尚未实现**：任意液体自由液面及流固耦合、组织纤维撕裂、可解开的包装、独立蛋壳破裂、凝固回成原形、油脂析出与所有酱汁的挥发/乳化化学、每一种食材专属完整温度/相变参数。现有黄油原画含包装，液化展示不会单独留下包装；这是素材与交互缺口。锅内液相和遮挡仍是二维近似。

**已实现但未人工验收**：长时间自由乱操作、多人配方组合、人耳逐条音色与混音、系统输入法及连续系统鼠标试玩。自动化与实际 GPU 检查不等于这些人工验收。另 13 张黑底蔬菜 JPEG 和白底番茄原图的透明替换仍未完成，详见原素材报告；本轮没有重绘它们，也不把旧缺口写成已完成。
